Product surface · Four agents, one stack

Four products. One feedback loop.

Every prediction Snapcount ships is the output of four cooperating systems: SnapScore learns from history, SnapForm adjusts for the present, SnapPro turns predictions into decisions, and NFLooker explains why in plain English.

01 / SnapScore
SnapScore
Per-player projection model

XGBoost on a walk-forward harness across 2016–2024. Eight player-level targets, validated weekly on 2024 wks 9+, holdout-quarantined 2025 for the ship-gate. Anti-leakage gate enforced at split-time.

Closed-form formulas that translate live signals into a multiplier on SnapScore baselines. Injury decay curves, weather penalties, snap-share trajectories. Authored under snapform/formulas/; refreshed weekly by Adam.

How it works · Six stages, idempotent

Ingest → Validate → Freeze → Features → Harness → Models

Every stage is re-runnable. Every stage refuses to start if the upstream stage failed. The validator hard-fails the pipeline before bad data reaches modeling.

01 / INGEST
nflreadpy

Pull 27 nflverse sources for 2016 → current NFL season. Auto-derives season range from today's date so a 2026 ingest just works.

~46s · 484K PBP rows
02 / VALIDATE
3-layer validator

Schema drift (added/removed/dtype-changed cols), coverage invariants (per-season weeks, dual-schema integrity), in-season currency. Hard-fails on regression.

14 live-critical sources
03 / FREEZE
Two-tier slice

Predicate-based filtering carves out validation (2024 wks 9+) and holdout (2025 entire). Two anti-leak invariants enforced. Stale parquets unlinked.

21 sources × 2 slices
04 / FEATURES
Layer 0 + 1 (M3 adds 2/3/4)

Layer 0 = id-keys + target. Layer 1 = lagged player-game features (last-game, last-3, season-to-date) + team-change indicator. Anti-leakage gate at build time.

19+ features per QB-week
05 / HARNESS
Walk-forward CV

Predict at (S, W) using only data with (season < S) OR (season == S AND week < W). Imputer + scaler fit per fold. 17 boundary tests pin the contract.

14 folds · 2024 wks 9-22
06 / MODELS
Ridge → XGBoost

Same harness, plug-in models. Ridge for the linear floor; XGBoost with target-aware objective (squared-error for yards, count:poisson for TDs).

8 (position × target) baselines
M4 baseline · Walk-forward CV · 2024 wks 9-22

Numbers, not narratives.

Honest unfiltered baseline on the 2024 validation slice. Five model milestones in. M4 XGB beats the M1 lagged-only floor by 20-25% MAE on yards targets. Static player attributes (added in M4) hit a ceiling; M5 ensembles and M6 Bayesian outputs are the next leverage.

In plain English
What MAE means

"MAE" = mean absolute error. On QB passing yards, MAE 51 means the model is off by about 51 yards per game on average.

For context: an actual QB's passing-yards game-to-game variance (their own week-to-week swing) is in the 70-90 yards range. Our model's error (51) is now well below natural noise — meaning it can reliably rank QBs by likely production, even if individual game predictions still carry a one-touchdown-drive of error. The PRD ship-gate is ~25 MAE. We're roughly halfway there with M4.

Out-of-time test · Sacred ship-gate

2025 is locked in a vault.

2025
Holdout season
285 games · 48,771 PBP rows
517,851 depth-chart events
quarantined since M0

The AutoResearch loop never reads holdout. Period.

Every Ridge fit, every XGBoost fit, every walk-forward fold during the modeling loop sees only the training surface (2016–2024 minus the 2024 wks 9+ validation slice). The 2025 season is physically separated into data/holdout_2025/, frozen at M0, and read exactly once — at the explicit ship-gate before SnapScore reaches production traffic.

Belt + suspenders: run_baseline.py drops season == 2025 from the input frame BEFORE the harness even sees it. The harness's walk_forward_splits filters again. holdout_seasons is honored by both walk-forward and season-rollover splits. Three independent gates, all enforced.

Engineering principles · Not negotiable

The boring stuff that makes the predictions trustworthy.

Anti-leakage at split-time

The walk-forward harness invokes the leakage validator BEFORE the first fit. Any feature pipeline that references a participation column, a post-game PBP outcome, or measured weather/officials hard-fails when live=true. 16 tests pin the block list against the actual participation.parquet schema.

eval/leakage.py · 4 surfaces

Schema-drift validator

Every ingest writes a baseline schema. Future ingests diff against it: removed columns, dtype changes, missing seasons, missing weeks per season, depth-charts dual-schema invariants. In-season runs additionally check 14 live-critical sources for currency.

scripts/validate_raw.py · 3 layers

Walk-forward correctness

Predict at (season S, week W) reads ONLY rows where (season < S) OR (season == S AND week < W). Imputer + scaler fit on each fold's train rows separately — no global statistics leak across folds. 17 boundary tests prevent regressions.

eval/harness.py · tests/test_harness.py

Independent codex audits

Every milestone gets reviewed by a different LLM (OpenAI codex) with adversarial intent. M0 had 5 review rounds; M1 had 1; M2 had 1. Every CRITICAL/HIGH finding closed before tag. The modeling lane doesn't self-approve.
